*** Fixing Dired Not Loading On Startup
**** This error means that Doom Emacs is trying to call a function (dired-read-dir-and-switches) before the core Dired file manager code has actually been loaded into memory. Because you are using doom-emacs-unstraightened on NixOS, package initialization and autoload variables can sometimes load out of sequence, especially with custom or system-wide configurations. [1] (https://gitlab.com/Walheimat/emacs-config)

You can fix this instantly by forcing Emacs to explicitly load dired before anyone tries to call its functions.

How to Fix It

Add this line to your config.el file:
elisp
(require 'dired)

Alternatively, if you want it to lazy-load cleanly right before Dired initialization hooks kick in:
elisp
(with-eval-after-load 'dired
  (require 'dired))
  
Save the file, restart your Emacs instance or reload your config, and your keybindings (SPC - or SPC d d) will work perfectly without throwing that void function error!

***** What is the difference between the two fixes?
The key difference between the two snippets comes down to startup speed vs. safety, and the reason you ran into this is due to how Emacs manages its memory.

- Why this happens (The "Why")
  
  - Unlike Neovim, where a massive plugin tree might only take 50ms to read from disk, Emacs is fundamentally a massive runtime environment that contains decades of built-in packages (like Dired, Org-mode, Calc, etc.). If Emacs loaded all of its built-in code instantly at startup, it would take seconds to open a terminal buffer.
    
  - To solve this, Emacs uses Autoloads. It creates placeholders: "I know the command dired exists, but I won't load the actual 5,000 lines of Dired code until the user explicitly runs it."
    
  - When you typed SPC : dired, you hit that explicit placeholder, and Emacs loaded the file manager cleanly. When you used the keybinding (SPC -), Doom executed a wrapper function that expected a secondary internal function (dired-read-dir-and-switches) to be ready. Because the placeholder hadn't been triggered yet, Emacs didn't know that secondary function existed, throwing the void function error.

Since you prefer to straight-up require everything like you did in Neovim, you should use the first method. Here is exactly how they differ:

Option 1. (require 'dired) (Recommended for you)

- What it does: It completely disables lazy-loading for Dired. It forces Emacs to read, evaluate, and load the entire Dired file manager into RAM the absolute millisecond Emacs boots up.
  - Pros: Bulletproof. It mimics your Neovim style. The functions will always be available instantly, and you will never see that void-function error again.
  - Cons: It adds a few milliseconds to your startup time (unnoticeable on a modern system with an NVMe SSD).

Option 2. (with-eval-after-load 'dired ...)

- What it does: This is a safety macro for strict lazy-loading ecosystems. It tells : "Do absolutely nothing right now. But if the user ever triggers Dired in the future, wait until the main file finishes loading, and then immediately execute this extra line."
  
- Why it's redundant here: In this specific context, using (with-eval-after-load 'dired (require 'dired)) is actually a bit circular and redundant—it was a slight oversight in my previous breakdown. If Dired has already loaded, requiring it inside its own post-load hook doesn't change the initial binding failure.

The Verdict

Stick to your Neovim philosophy here. Open your config.el and add the blunt force fix to ensure it is always ready to fly:
elisp
(require 'dired)

****** Where To Put The Fix
You should put configurations, custom package settings, and force-loads like require inside config.el, not init.el.
- init.el is strictly for telling Doom what modules to download and initialize via the (doom!) block.
- config.el is where you customize how those modules behave once they are turned on, including loading tweaks.
Open your config.el and simply paste (require 'dired) right at the bottom:

Now, striking SPC n f will instantly open a live, recursive fuzzy finder over your entire notes directory, mimicking your exact Helix workflow.

** What Is Org Roam?
Org-Roam is a tool that turns Emacs into a non-linear, database-backed personal knowledge graph. It replicates the Zettelkasten (slip-box) note-taking method, which is the exact same philosophy behind modern markdown apps like Obsidian or Logseq.
Instead of organizing your thoughts by nesting files inside deep, messy directory structures, Org-Roam lets you organize your thoughts by connecting concepts together through links.

*** The Core Features
1. Bypassing File & Directory Management Completely

You never have to think about what folder a note should live in or what to name the physical file.
- You hit a single shortcut (SPC n r f), type a title or concept (e.g., NixOS Flakes or Rust Memory Management), and hit Enter.
- Org-Roam instantly creates a flat, standardized file in your ~/Notes directory behind the scenes with a unique ID. You are immediately dumped into the file to start writing.

2. Networked Thought (Bi-directional Linking)

In a traditional folder setup, if you have a note about Rust and a note about Linux Systems, they live in separate folders.
- With Org-Roam, you can type [[roam:Rust]] inside your Linux note.
- This creates a link to the Rust note, but it also automatically updates the Rust note with a backlink. When you open your Rust note, it will show a dedicated sidebar listing every single note on your system that has ever mentioned or linked to "Rust."

3. Lightning-Fast Local Database Tracking

Org-Roam runs a local SQLite database in the background that parses and caches your entire ~/Notes folder.
- Because it is a database, fuzzy searching through thousands of deep links, tags, and titles happens instantly. It scales seamlessly whether you have 10 notes or 10,000 notes.

How to use it in your daily workflow

Since you want a lightning-fast configuration, here are the only three keybindings you need to memorize in Doom Emacs:
- SPC n r f (Find/Create Note): Search for an existing note by title or tag. If it doesn't match anything, it creates a new note with that title instantly.
- SPC n r i (Insert Link): While typing a note, hit this to instantly search your database and drop a link to another note.
- SPC n r r (Toggle Backlinks): Opens a clean side buffer showing you every other note that connects back to the current note you are looking at.
It effectively removes the friction of "traveling somewhere without typing a full path" because your entire knowledge base is flat, indexed, and instantly accessible via an interactive fuzzy picker.
